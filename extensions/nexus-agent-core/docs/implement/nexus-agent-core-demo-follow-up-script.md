# Nexus 演示脚本：跟进同事交付（给普通用户看，约 10 分钟）

> 2026-11-12。演示的是“工作 + 承诺 + 跟进”这一条线：在聊天里把一件事登记下来，记下同事的承诺，让助手起草跟进方案，你在页面上确认，助手去看一个网页有没有变化，承诺办结后方案自动收尾。
> 全程只用 OpenClaw 聊天和 Nexus 页面，**不敲命令**。命令只出现在“演示前准备”里，由你在演示前做完。
> 每一幕都写了“聊天说法 + 页面兜底”：助手没按预期做时，当场改走页面，演示不会卡住。
> 这份只讲主线。暂停 / 恢复 / 停止某项检查、两个窗口冲突、删除工作的连带结束，不在本稿里，需要时单独加。

## 一、先说清楚几件事（开场前心里有数）

- **检查现在只能读网页。** 邮件、会议还没有接入，所以场景用“同事报告的交付状态写在一个公开网页上”。不要在演示里说“它会看邮件”或“它会看会议”；被问到就如实说：后面会接，现在只读网页。
- **助手只能起草，不能开始。** 它给出的跟进方案是草稿，什么都不会跑，必须你在页面上点“确认并开始”。这是演示的重点，要讲出来。
- **跟进不会对外发任何消息。** 检查只读取和汇报。页面上方案里写着“不会做：自动催办、对外发送任何消息”。
- **助手的话每次不同。** 下面“看到”写的是应有的结果，不是它的原话。

## 二、演示前准备（演示前 15 分钟做完）

1. **模型能正常对话。** 在聊天里随便问一句，能回答就行。模型没登录的话，第 5 幕的检查会显示“检查没完成”，演示就废了。
2. **准备一个能随时手动改的公开网页**，内容先写成：
   `小王 · 11 月季度报告 · 状态：未提交`
   比如 GitHub Gist。用 **页面地址**（gist.github.com 开头），不要用 raw 地址：raw 地址通常有几分钟缓存，改完网页检查看不到变化。具体缓存多久以彩排时为准。
3. **确认助手读得到这个网页。** 在聊天里说“请读一下 <演示页面地址>，告诉我页面写了什么”，能说出“未提交”才算通。读不到，就换一个页面或检查网络，不要带着问题上场。
4. **确认两个新工具已放行。** 助手起草跟进方案要用 `nexus_schedule_propose`、`nexus_schedule_get`。打开 App 自带的命令行执行：
   ```bash
   openclaw config get tools.alsoAllow | grep -c nexus_schedule_propose
   ```
   输出 1 说明已放行。输出 0 说明这台机器装的是旧版预设，需要用新的安装包重装（预设版本 5，44 个工具），或手工把这两个名字补进 `tools.alsoAllow` 后重启网关。
5. **清掉旧日程。** 之前验证留下的日程如果还在运行，演示时会冒出不相关的检查记录。把它们先暂停掉（用上一轮给你的批量暂停命令）。
6. **窗口布局：** 左边 OpenClaw 聊天，右边 Nexus 的“工作”页，字号调大，界面语言用中文。
7. **日期：** 下面脚本里的“11 月 13 日”换成演示当周的周五，和你在网页里写的一致。
8. **完整彩排一遍。** 起草方案是模型自己判断的，不彩排一次不要上场。彩排留下的工作，在“工作”页点进去用“删除工作”清掉（它名下的方案和日程会一起结束）。

## 三、演示脚本

### 第 0 幕：开场（半分钟）

- **做：** 打开 Nexus 的“工作”页。
- **讲：** “很多事不是一句话能办完的，比如‘等同事交一份报告’。Nexus 把它变成一件工作，记下谁答应了什么、什么时候交，还能定期替你看一眼有没有动静。助手帮你起草，决定权在你手里。”

### 第 1 幕：聊天里登记一件工作（1.5 分钟）

- **对助手说：** “我答应了老板，下周五前要拿到小王的 11 月季度报告。帮我把这件事登记成一件工作。”
- **看到（聊天）：** 助手登记好，告诉你工作的名称。没说的信息它会问，不会编。
- **看到（Nexus）：** “工作”页刷新（或点一下刷新），多了一件工作，点进去是详情页，里面有“承诺事项”和“跟进”两个区块，现在都是空的。
- **兜底：** 助手只是聊天没动手，就说“请用 Nexus 的事项工具把这件事登记下来”。
- **讲：** “这是一件工作。接下来的承诺和跟进，都挂在它下面。”

### 第 2 幕：聊天里记下同事的承诺（1.5 分钟）

- **对助手说：** “小王答应本周五（11 月 13 日）下午 6 点前把季度报告交给我。把这记成一项承诺，挂在刚才那件工作下面。”
- **看到（聊天）：** 助手说记好了，写明谁负责、什么期限。
- **看到（Nexus）：** 工作详情的“承诺事项”里出现一行：“小王 负责”，期限是周五 18:00，状态“待安排”，对方还没回应，下面标着“仅参考”。
- **兜底：** 助手没记，或没挂到这件工作下面：在“承诺事项”区块点“记录承诺”，要交付什么填“11 月季度报告”，谁负责选“对方”填“小王”，期限选“指定时间”。
- **讲：** “承诺只记一个人负责，对方有没有接受、有没有告知，都分开记，不会混成‘已经说好了’。”

### 第 3 幕：让助手起草跟进方案，它只能起草（2 分钟）

- **对助手说：** “帮我跟进小王这项承诺：每 15 分钟看一下 <演示页面地址>，只要页面上小王的报告状态变成‘已提交’，就算有变化，告诉我。先给我草稿，别自己开始。”
- **看到（聊天）：** 助手说已经存成草稿，**还没有开始**，要你去页面确认。如果它说“已经开始跟进了”，是它说错了，直接对它说“你没有权限开始，只是起草，请如实说”。
- **看到（Nexus）：** 刷新工作详情，“跟进”区块出现一份方案，标着“草稿，尚未开始”，里面写着：看什么 / 在哪看（那个网址）、多久看一次（每 15 分钟）、何时结束（这项承诺办结或取消时）、不会做（不自动催办，不对外发送任何消息）。
- **兜底（助手没起草）：** 对助手说“请用 nexus_schedule_propose 给这项承诺起草一份跟进方案，只起草，不要开始”。仍不行就走页面：在“承诺事项”里把这项承诺点“设为必要”，再到“人员”页找到小王的未结案承诺，点“继续跟进”，在弹出的审阅窗口里点“确认并开始跟进”。这条路径会直接开始，跳过下面第 4 幕的确认，接着演第 5 幕。人员页的具体入口以实际页面为准，彩排时走一遍。
- **讲：** “助手只能写草稿，不能让它开始。你看，现在什么都没有在跑，要等你点头。”

### 第 4 幕：你在页面上确认（1.5 分钟）

- **做：** 在“跟进”区块的草稿上点“开始跟进”。弹窗标题是“确认开始跟进”，把内容念一遍：看什么、多久看一次、不会做什么。点“确认并开始”。
- **看到：** 方案状态变成“跟进中”，下面出现一项检查：“每 15 分钟”，有“下次检查”的时间，覆盖状态“按计划覆盖”，每项检查旁有“立即检查”“暂停”“停止跟进”几个按钮。
- **要是看到“受阻”：** 说明当前环境启动不了定时检查，页面会写明原因，不会假装在跟进。这属于环境问题，按“演示前准备”重新检查，不要硬演。
- **讲：** “点了确认，才会按这份方案去看。弹窗里写得很清楚：只读取和汇报，不发消息，不改外部的任何东西。”

### 第 5 幕：立即检查，看助手真的去读了网页（2 分钟）

- **做 1：** 网页现在还是“未提交”。点那项检查旁的“立即检查”。
- **看到：** 先显示“检查进行中”，等半分钟到一两分钟（取决于模型速度），“最近的检查”里出现一行：**没有变化**，后面有一句助手写的说明，大意是页面上小王的报告状态仍是“未提交”。
- **做 2：** 把演示网页改成：`小王 · 11 月季度报告 · 状态：已提交（11 月 13 日 17:40）`。保存。等上一次检查结束后，再点“立即检查”。
- **看到：** 这次是 **有变化**，说明写的是页面上状态已变成“已提交”。
- **如果结果不对：** 第一次报了“有变化”，或第二次报了“没有变化”：多半是网页缓存或助手没读新内容。对着“全部检查记录”看它写的说明，先判断它读到的是旧页面还是新页面。网页是旧的就稍等再查；网页是新的它却报没变化，这次如实讲，然后直接进下一幕，不要在这里耗时间。
- **如果显示“检查没完成”：** 通常是模型没登录或没响应，不是方案的问题。先回模型页重新登录，再点一次“立即检查”。
- **讲：** “这一步是助手自己去读那个网页，读完交一份报告：有变化、没变化，或者没能检查。它没法看的时候会明说‘没能检查’，不会假装一切正常。注意，它全程没有联系小王。”

### 第 6 幕：承诺办结，跟进方案自动收尾（1.5 分钟）

- **做：** 回到“承诺事项”，在小王这一行点“注明原因结案”。弹窗会先告诉你这会影响什么：下面一行写着这份跟进方案会收尾，已经在跑的检查先跑完（最多 30 分钟），之后不再检查，重新打开承诺也不会恢复。原因填“报告已收到”，确认。
- **看到：** 承诺显示“已手动结案”，下面写着你的原因。“跟进”区块里那份方案：没有检查在跑时当场变成“已结束（这项承诺已办结）”；如果刚好有检查在跑，先显示“正在结束”，那一次检查跑完就结束。
- **讲：** “承诺一办完，跟进就自己停，不会一直查下去。还有一点：这里是‘手动结案’，系统明说了它不等于‘核实过交付’，所以依赖它的工作也不会自动算完成。”

### 收尾（半分钟）

- **讲：** “助手帮你起草，你来决定；检查只读不发；办结就收尾。邮件和会议的来源，是下一步要接的。”
- **清场（演示后）：** 在“工作”页打开这件演示工作，点“删除工作”清掉。它名下的方案和日程会一起结束，承诺不受影响。这样下一次演示又是干净状态。

## 四、观众可能问到的问题

- **它会不会自己给小王发消息？** 不会。检查只有读取权限，方案里写明不对外发送；催办在人员页只出草稿，也不会替你发送。
- **它会不会没经过我就开始？** 不会。助手只能存草稿，开始必须你在页面上确认。
- **它看不了的时候怎么办？** 会记成“没能检查”，页面上显示覆盖不足，不会写成“没变化”。
- **能看邮件、看会议吗？** 现在还不能，现在只能读网页。后面接邮件和日历之后，同样只读。
- **为什么检查要用模型？** 因为要读懂页面内容、判断有没有变化，所以用模型读页面，再交一份结构化的报告。模型不可用的时候，检查会失败并如实显示。

## 五、跑偏时的应对速查

| 现象                 | 当场怎么办                                                     |
| -------------------- | -------------------------------------------------------------- |
| 助手聊了半天没登记   | 说“请用 Nexus 的事项工具登记这件事”                            |
| 承诺没挂到那件工作下 | 页面“记录承诺”手动补                                           |
| 助手说“已开始跟进”   | 纠正它：只是草稿，没开始                                       |
| 草稿没出现           | 说一次 `nexus_schedule_propose`，不行就走人员页“继续跟进”      |
| 方案显示“受阻”       | 环境问题，停下来按准备清单排查                                 |
| 检查没完成           | 模型登录问题，重新登录后再点“立即检查”                         |
| 检查结果和网页对不上 | 看“全部检查记录”里的说明，判断是缓存还是没读到，如实讲，不硬撑 |
