# Goals（长期目标）G1 + G2 阶段小结

> 日期：2026-10-27。写给想快速了解"目标功能现在做到哪一步"的人，不需要读设计文档。细节见 `nexus-agent-core-goals-design.md` 第 13、14 节。

## 一句话

现在你可以在控制台里**建目标、记进展、给目标设数字度量**，Agent 能读你的目标、帮你起草，但**不会替你做主**；目标还只是"被动记账"，不会主动提醒你、定期回看，这是下一阶段的事。

## 今天完成了什么

### G1：目标本身（已在真实界面验收）

- **能建目标**：控制台有"目标"页。点一个类别（理财 / 兴趣 / 其他）会开一个对话，Agent 按类别问你几个问题，再把目标存下来。
- **Agent 只能提议，不能替你拍板**：Agent 自己想到的目标进"待确认"，只有你在控制台点批准才生效；只有你能把目标标记为完成（点完成前还会弹确认框，避免误点）。
- **能记进展**：给目标添加记录；一层嵌套（大目标下挂小目标）；最多 20 个进行中的目标。
- **能删干净**：先放进回收状态，确认后彻底清除，并留一张清除回执；清除目标不会误删它关联的事项。
- **有安全底线**：记录里如果出现密码、卡号之类的敏感内容会被拦下；不同用户的数据互相隔离。
- **验收中顺手修了 5 个问题**：勾选框误触、Agent 误用"提议"绕过追问、批准时跳过追问、第二次建目标冲突、模型过载后的重试。

### G2：进展与度量（今天做完，Mac 上验收通过）

- **度量**：每个目标可以加最多 10 个数字度量，比如"本周练习时长 12 / 10 小时"，有进度条，数值达到目标时自动写一条"已达到目标"的记录（目标本身不会因此自动完成，仍由你决定）。
- **两种数字来源**：
  - "我自己填"——你手动输入，标签是"自述"；
  - "来自事项里的声明"——数字取自某个事项里 Agent 登记的声明，并显示这条声明的可信状态（已声明 / 已被证据支持 / 已核验 / 被反驳 / 未知）。
- **声明驱动的度量更谨慎**：只有声明被证据支持或核验，才算"已达到"，Agent 光是口头声明不算数。
- **理财类目标只能手填**：钱的数字不让 Agent 的声明来驱动，这是故意的。
- **记录可以关联事项和声明**：添加记录时可选一个事项（再选一条声明），记录上会显示事项名和声明状态；不选就显示"自述"。
- **Agent 只读不写**：Agent 能看到你的度量和状态，但没有任何工具能改度量。
- **代码质量**：云端 610 项测试通过；你在 Mac 上跑的格式化、代码检查、测试、打包也全部通过。

## 还不够的地方

**用起来能感觉到的：**

1. **"被反驳"在界面里无法触发。** 声明状态由证据决定，你不能手动改，Agent 也只能登记"已声明/未知"；自动核验目前只覆盖"某操作确实执行过"这一类声明。技术上有一个撤回声明的接口（会让声明变成被反驳），但只有命令行入口，没有按钮。这个标签的显示逻辑只在云端测试里验证过，没有在真实界面里见过。
2. **目标不会主动找你。** 没有定期回看，也没有提醒。数值达到目标，只是多一条记录，不会通知你。
3. **打开的详情窗是"快照"。** 在窗口开着的时候事项或声明变了，要关掉再打开才能看到新状态。
4. **选事项没有搜索框**，只列最近 100 个事项、每个事项最多 100 条声明。
5. **事项状态显示的是原始英文状态名**（如 `executing`），没有翻译。
6. **声明的值必须是数字**（或 `{"value":数字}`），否则显示"暂无数值"。

**依赖模型表现的：**

7. **选项卡片不保证出现。** 创建对话里，Agent 是否弹出点选卡片取决于模型；理财类有时只给文字选项（直接回复也能走通）。
8. **模型过载时会报错**，属于提供商瞬时问题，重发即可，不会重复建目标。
9. **Agent 进入代码模式时调不到目标工具**，目前靠提示词引导，没有服务端兜底。

**还没做的功能：**

10. 没有"技能"：Agent 对各类目标的引导靠注入提示词，没有像样的理财、兴趣专用指南（G4）。
11. 真实模型提供商、个人 Wiki、通知与审计相关事项，按你的决定后置。

## 下一步计划（2026-10-27 原计划；最新进展见文末的更新）

建议顺序（每步做完你验收一下再走下一步）：

1. **先提交 G2。** 把 G2 的改动提交进 git（需要时我给你提交说明）。
2. **（可选）G2.1 小补丁**，都是小改动，可以挑着做：
   - 给声明加"撤回"按钮，让"被反驳"能在界面里验收；
   - 详情窗在事项或声明变化时自动刷新；
   - 选事项时加搜索框、翻译事项状态。
3. **G-S1 小验证（G3 的前置）。** 先花很小的力气确认：插件能否可靠地定时唤醒、并通过通知出口告诉你，且本机睡眠或关机后错过的回看怎么补。这一步不写功能，只回答"能不能做、怎么做"。
4. **G3 定期回看。** Agent 按周期回看进行中的目标，给你一份进展小结并提醒；包含错过后补跑和次数限额。依赖第 3 步的结论和通知出口。
5. **G4 技能。** 给理财、兴趣等类别写专用引导，让创建对话和回看更贴合类别。

后置不动：真实模型提供商、个人 Wiki、通知与审计的其他事项、文件库的遗留清单。

## 更新（2026-10-28）：G2.1 与 G-S1

- **G2.1 小补丁已实现，待 Mac 验收**：任务页的声明有了"撤回"按钮（带二次确认，不可恢复），撤回后目标度量会显示"被反驳"，这样上面"被反驳"那一项终于能在界面里验收；目标详情窗打开时，事项或声明变化会自动重画；选事项加了搜索框，事项和声明状态改成中文。
- **G-S1 结论（读宿主源码得出，探针实测待回填）**：电脑休眠醒来后，宿主会把所有到期的定时任务一次拉起，最多 8 个同时跑，没有"每次最多几个"的限制，也不会错开；错过好几个周期的每周任务只会补一次；网关重启后则最多立即补 5 个、其余错开 5 秒。所以"限流、错过太久就跳过"必须由 Nexus 自己做。建议 G3 改成**每个用户一个"回看调度员"任务**，由它挑最多 N 个到期的目标，而不是每个目标一个定时任务。详见目标设计文档第 15 节。
- **下一步**：你验收 G2.1 → 在 Mac 上跑一条探针命令把 G-S1 的实测补齐 → 决定通知的第一条出口 → 开始 G3。

## 更新（2026-10-28 晚）：G2.1 验收通过，G2.2 完成，G-S1 实测回填

- **G2.1 验收通过**：撤回一条声明后重开目标详情，度量显示"被反驳"。
- **你发现的"关联一直为空"**：不是 bug，是两个概念。记录上选的事项和声明，只是这条记录自己的"出处"；目标的"关联"表示"这个事项属于这个目标"（一个事项只能属于一个目标），以前只有 Agent 能建。**G2.2 已补上**：关联区有"添加关联"和每条的"移除"（带确认）；添加记录选了事项时可以勾选"同时把这个事项关联到目标"（默认不勾）；被拒绝时给出中文原因。
- **G-S1 实测**：休眠醒来后，12 个错过了 3 个周期的每周任务各只补一次；网关重启后立即补 5 个、其余每个错开 5 秒，agent 任务则全部推迟 2 分钟再开始。和源码结论一致。"同时最多跑几个"那一项第一次没测准，改成真实定时器后你重跑过：休眠醒来时同时在跑的正好是 8 个，和源码一致。

## 更新（2026-10-28 深夜）：G3a 回看提醒层已实现，待你试用

你说"先试试控制台徽标加对话内提示，看看这个效果好不好"，所以这一步只做**提醒**，不做自动回看：

- **每个目标自己设回看周期**（每周 / 每两周 / 每月，默认不提醒），在目标详情的"定期回看"区选。
- **到期了怎么提醒你**：目标列表里这个目标后面有"该回看了"，"目标"标签后面显示数量（如"目标 (1)"）；你下一次开始聊天时，助手在回答完你的问题之后，会用一句话提一次"有目标到回看时间了，现在看还是稍后"。**每个到期日只提一次**，你回应或点"稍后（2 天）"之后就不再追。
- **你同意之后**：助手读这个目标，用两三句话总结进展，只问一个问题，把你的回答记成一条进展，然后把提醒标成"已回看"（下次日期顺延一个周期，活动里留一条系统记录）。说"稍后"则推迟 2 天。
- **助手不能自己设周期**，只能在你同意之后标"已回看"或"稍后"；已完成、待确认的目标和创建目标的对话里都不会提示。
- **刻意还没做**：没有后台定时任务、助手不会自己写进展草稿、没有"忽略几次自动暂停"、没有手机推送。提醒只在你打开控制台或开始聊天时出现。这些要看这一步的效果再决定做不做。
- **要你判断的**：这种提示是有用还是烦？一次到期提一次合不合适？详见目标设计文档第 16 节的验收清单。
